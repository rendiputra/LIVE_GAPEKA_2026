## 15. Risks and anomalies

1. **Text-stream order is unreliable.** On KRL pages the stream emits `Berangkat` before `Datang` (PDF 1001: x=268 -> 11:54, x=314 -> 11:55). Rows and columns must be rebuilt from x/y coordinates. This is now Hard Rule 11.
2. **Two trains per page.** 979 of 1,426 train-table pages contain two or more table headers. A one-table-per-page parser will silently drop half the data.
3. **Printed page numbers restart per book.** Five boundaries, listed in section 8. Any code that assumes a single offset will mis-map pages.
4. **12 image-only pages** (1-5, 1676, 1702, 1707, 1740, 1776, 1813, 1819). None contain timetable data; no OCR is planned.
5. **Inline footnotes** such as `= ka 46 (ka 46 //)` and `// ka 5014 (ka 5014 =)` sit inside the row stream and will corrupt a naive row split.
6. **`Ls` and `-` are not times.** `Ls` in Keterangan means pass-through; `-` means an empty cell. Both must become `null`/`pass`, never a time.
7. **Header count != train count.** 636 `Relasi` headers cover 319 distinct train numbers; KRL and freight tables have no such header.
8. **The stringline annex is not machine-readable.** It is a chart, not a table. It is classified for completeness and must not be parsed.
9. **`legend` is empty.** The chart legend lives on PDF page 51 inside a stringline page. If a later Gapeka prints it separately, rule 9 will catch it.
10. **Section boundaries are marker-based.** If the Gapeka format changes, the markers in `pipeline/classify.py` must be re-verified before trusting the section field.
