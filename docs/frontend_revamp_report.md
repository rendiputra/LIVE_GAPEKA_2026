`e2e/`.

axe regressions, focus management, legend/zoom/dock collision, mobile inspector and board
anchoring, attribution collapse, and copy/error states.

## 4. Defects found by this verification and fixed

These were not cosmetic; each had a failing gate behind it.

### 4.1 Worker fetched the schedule from the wrong URL under `base: "./"`

`vite.config.ts` gained `base: "./"` so the bundle can live under a sub-path. That
exposed a latent bug: inside a Web Worker a relative URL resolves against the **worker
script** (`/assets/...`), not the document, so `./data/manifest.json` 404'd and the app
sat at “0 KA”. The page now resolves the URL with `document.baseURI` and sends it in the
`init` message (`WorkerRequest.init.dataBaseUrl`); the worker falls back to
`import.meta.env.BASE_URL` only when no URL is supplied. `e2e/subpath.spec.ts` proves the
whole chain works from `/sub/`.

### 4.2 Station labels were never pushed after the schedule landed

`gapeka-stations` was created on `style.load`, which usually beats the 1.1 MB schedule, and
no effect refilled it. The 391 rails had already been fixed this way; the station source
had not, so labels could stay absent for the whole session. `pushStations()` now runs in
the same snapshot effect as `pushRail()`, and both publish read-only counts
(`data-rail-features`, `data-station-features`) so the e2e suite can prove the geometry
reached MapLibre without a canvas pixel probe.

### 4.3 The mobile dock overflowed the viewport in Simulasi

At 390 px the dock was wider than the screen once the `Kembali ke Live` button appeared
(Simulasi only), pushing both edges off-screen and clipping the button. The dock now:

- caps at `max-w-[calc(100vw-1.5rem)]`;
- lets the 24 h scrubber flex into the remaining space;
- hides the `−15m` / `+15m` nudges below `sm`, where the scrubber already does the same job.

Acceptance test 5 now asserts the dock is fully inside the viewport in Live, in Simulasi
and after returning to Live, at both viewports.

### 4.4 Two e2e assertions were wrong, not the app

- The station-board “bottom anchored” test asserted `y > height / 2`. A seven-row board is
  ~552 px tall at 390 × 844 and legitimately starts above the midpoint; the test now
  asserts the actual invariant (bottom edge flush with the dock, same 8 px gap).
- The timezone test read the inspector before the worker replied for the scrubbed instant,
  so it could catch a one-frame “Tidak aktif” state. It now waits for the running state;
  8 repeats × 2 projects pass.

## 5. Performance

From `data/review/frontend_lighthouse.json` (mobile 390 × 844, tiles blocked — the numbers
describe the app shell and the schedule payload, not the tile provider):

| Metric | Value |
|---|---|
| Performance | 77 |
| Accessibility | 100 |
| Best practices | 96 |
| SEO | 91 |
| First contentful paint | 903.9 ms |
| Largest contentful paint | 5733.9 ms |
| Total blocking time | 164 ms |
| Cumulative layout shift | 0.00198 |
| Speed index | 1856.9 ms |
| Total byte weight | 740507 B |

Schedule payload (`data/review/frontend_export.json`): 1,157,433 B raw / 270,475 B gzip
for 625 trips, 389 stations and 391 segments, content hash `2f8588adc0168c0e`.

`make frontend-lighthouse` referenced a script that did not exist; it now exists at
`frontend/e2e/lighthouse.mjs` and writes the JSON above. It blocks
`tiles.openfreemap.org`, `tiles.openrailwaymap.org` and `tile.openstreetmap.org` via
Lighthouse's `blockedUrlPatterns` (a `page.route` stub cannot work: Lighthouse opens its
own tab). `lighthouse@^13.6.0` was added as a dev dependency for this, matching the major
used by `web/`.

LCP 5.7 s is the one number worth watching. It is dominated by the MapLibre bundle and the
first schedule paint, not by layout work (TBT 164 ms, CLS 0.002). No optimisation was
attempted in this turn; it is recorded here rather than hidden.
